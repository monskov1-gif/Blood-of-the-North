# Как работать с владельцем проекта

## Темп и автономность

- Владелец ждёт, что Claude **делает работу целиком и сам**: получил список правок → сделал все пункты →
  проверил скриншотами → прогнал критиков → закоммитил → запушил → опубликовал → коротко отчитался.
- Не спрашивать разрешения на обычные шаги (коммит, пуш в рабочую ветку, публикация новой версии,
  пересборка атласа, переработка сцены по замечаниям критиков). Всё это уже разрешено.
- Спрашивать только когда решение по-настоящему за владельцем (сюжет, новый арт, который нельзя
  сделать кодом, неоднозначный вкусовой выбор с двумя равными вариантами).
- Большие задания приходят списком пунктов (часто 5–10 + большой бриф). Делать все, в отчёте —
  по пунктам, что сделано; что не сделано — честно и почему.
- Если владелец прерывает и уточняет — сразу переключиться на уточнение, не доделывать старое.
- Длинные рендеры и проверки запускать в фоне; пока идут — делать следующее.

## Формат ответов

- По-русски, коротко. Отчёт: что сделано (по пунктам), оценки критиков таблицей «было → стало»,
  что осталось, ссылка на сайт после публикации.
- Без технических потрохов, если владелец не спросил (имена функций, диффы — только по запросу).
- Не обещать «посмотрю», если можно сразу сделать.

## Что владелец ценит

- Атмосфера: северный городок Уайтхорс (Юкон), поздняя осень → первый снег, холодный свет,
  потрёпанные интерьеры, реализм деталей (больница выглядит как настоящая региональная больница,
  машина — как настоящий полицейский седан).
- Пиксель-арт регистр спрайтов: 1 px ≈ 1 см, всё окружение в том же «зерне».
- Кинематографичность: свет из окон, блики объектива, глубина переднего плана, но **персонаж всегда
  читается** (ничто не должно закрывать Джулиана).
- Строгое следование референсам, которые он присылает («строгий пример, а не примерный референс»).

## Что уже отвергалось (не повторять)

- Перерисованная / «исправленная» / сгенерированная голова Джулиана; толстая шея; шея строго вниз
  посреди торса. Правильно: копия оригинальной головы с шеей, вынесенной вперёд, как на кадрах-исходниках.
- Машина как «освещённая коробка»; город вокруг машины (вокруг должно быть чёрное, город — только в окнах).
- Полупрозрачные текстуры в дверных проёмах.
- Одинаковая музыка везде (у каждой локации/состояния своя тема).
- Блик, «как получится» — блик должен повторять референс `docs/claude/flare_reference.jpg`.
- Чисто белые пересветы окон.

## Ресурсы, которые присылает владелец

- **Основной канал для арта — PNG с прозрачностью, загруженный владельцем в репозиторий** (рабочая
  ветка, обычно корень или `incoming/`). Забрать `git pull`, перенести в `tools/art/` (git mv), обработать.
- Картинки приходят в чат (сохраняются в `images/` в каталоге сессии). Сохранять важные в репо
  (`tools/raw/…` для арта, `docs/claude/…` для референсов).
- Ссылки на Яндекс.Диск из контейнера не открываются (прокси 403) — попросить приложить файл в чат.
- Генерации картинок нет (ChatGPT Go без API). Новый арт делает владелец сам и присылает; Claude
  обрабатывает его через `tools/process_art*.py` → `tools/build_sprites.py`.

## Окружение (облачная сессия)

- Контейнер эфемерный: всё важное — в репо и запушено. Временные файлы — в scratchpad сессии.
- После перезапуска контейнера локальный сервер `:8765` умирает — поднять заново, иначе скриншоты
  молча не обновляются (проверять время файлов).
- GitHub — через MCP-инструменты `mcp__github__*` (gh CLI нет); git push работает напрямую.
- Коммиты заканчиваются строками атрибуции из системного напоминания сессии. В коммитах и коде не
  упоминать идентификаторы моделей.
