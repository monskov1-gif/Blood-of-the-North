# Версии и публикация на сайт

**Постоянное разрешение владельца (2026-10-08): каждую новую версию выкладывать на сайт без
лишних вопросов.** Не спрашивать — публиковать и прислать ссылку.

## Версия

- Каждая правка кода (каждый законченный набор изменений, который уходит владельцу) поднимает
  версию на **0.01**. Менять в трёх местах:
  - `src/version.js` → `export const VERSION = '0.10';`
  - `index.html` → `<div class="boot-ver">demo v0.10</div>`
  - `README.md` → первая строка `… · v0.10`; при заметных новинках дописать раздел в README.
- Обновить `docs/claude/project.md` (раздел «Состояние»), если изменилось что-то существенное.

## Коммит и пуш

1. Проверка синтаксиса изменённых модулей: `node --check --input-type=module < file.js`.
2. Скриншоты + критики (`critics.md`) для визуальных изменений.
3. `git add -A && git commit` — сообщение по-английски, описательное; в конце — строки атрибуции из
   системного напоминания текущей сессии. Без идентификаторов моделей в тексте.
4. `git push -u origin <рабочая ветка>` (рабочую ветку задаёт сессия).

## Публикация (GitHub Pages)

Сайт https://monskov1-gif.github.io/Blood-of-the-North/ собирается GitHub Pages с ветки
**`claude/admiring-turing-t5ns0m`** (корень). Публикация = перемотать эту ветку на текущий коммит:

```bash
git fetch origin claude/admiring-turing-t5ns0m
git merge-base --is-ancestor origin/claude/admiring-turing-t5ns0m HEAD && echo fast-forward-ok
git push origin HEAD:claude/admiring-turing-t5ns0m
```

- Если ветка сайта не является предком текущего коммита (кто-то правил её отдельно) — слить её в
  рабочую ветку (`git merge origin/claude/admiring-turing-t5ns0m`), разрешить конфликты, затем пуш.
  Никогда не делать force-push в ветку сайта.
- Сайт обновляется через 1–2 минуты. Проверить: версия на экране загрузки (`boot-ver`).
  Из контейнера сайт может не открываться через прокси — тогда проверить, что пуш прошёл
  (`git ls-remote origin claude/admiring-turing-t5ns0m`), и дать владельцу ссылку.
- В отчёте владельцу: номер версии и ссылка на сайт.
